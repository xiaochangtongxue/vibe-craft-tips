# 016 · Toast 和 Notification 怎么选

原帖：https://x.com/Kubai087/status/2120682993563922586（第 0–5 节判断规则和数值来自原帖随附的 Prompt）

## 原理

两者的分界不在样子，在「谁引起的、用户要不要处理」：

- **Toast**：回应用户刚做的事，出现在他正在工作的地方。短、不打断、自己消失。可以带一个按钮（通常是撤销）配倒计时；耗时的操作先显示进度，完成后原地变成结果。
- **Notification**：不是用户此刻引起的消息，来自他人或系统（提及、回复、付款、截止、安全提醒、报告生成）。内容可以和当前操作无关，要让用户看到但不必立刻打断（这是它和弹窗的区别）。一直保留到处理或关闭，多条堆叠，可带操作按钮，并且能在铃铛后面的列表里再找到。
- **都不是**：必须由用户处理的事不能交给 Toast。不可撤销的操作在执行前确认；需要修复的失败留在出错的那一项上，直到解决。

这一期的 Prompt 是「先判断、再建议、只改用户同意的」：先读产品，逐条判断每条提示该是哪一种，给出表格，用户选了再动手；样式改造是可选的第二步。

## 范围

改用户的产品，不做 demo：用户的代码、技术栈、组件、token、圆角阶梯、字体和文案风格。不经询问不加依赖、不加新的状态库、不引入新的视觉模式。下面所有数值都是起点。

## 1. 各自管什么

**Toast**：回应用户刚做的事，在他工作的地方；短、不打断、自己消失。三种：

| 类型 | 用途 | 形态 | 例子 |
|---|---|---|---|
| 状态 Status | 确认结果，省得用户去查 | 图标 + 几个字，没有按钮 | 「链接已复制」 |
| 操作 Action | 操作已经执行，Toast 里放可能的下一步（通常是撤销） | 一行字 + 一个按钮 + 关闭；停留够长，显示剩余时间 | 「任务已归档 · 撤销」 |
| 进度 Progress | 需要一会儿的工作 | 先表明进行中，再原地变成结果，附查看按钮 | 「正在上传 brand-guide.pdf」→「已上传到文件 · 打开」 |

**Notification**：用户此刻没有引起的消息，来自他人或系统：提及、回复、付款、截止、安全提醒、生成好的报告。可以有标题、几行文字、最多两个操作。每个页面都显示；停留到被打开、处理或关闭；可以同时显示多条；还要存进能再找到的地方（铃铛后面的收件箱或列表，带计数）。

**都不是**：

- 表单错误、某个字段的问题：显示在字段旁边。
- 用户必须修复的失败（上传失败、付款没成功）：留在那一项上，带修复入口，直到修好。几秒后消失的 Toast 不够。
- 不可撤销的操作：执行前确认（按钮旁的二次确认，影响大时用对话框，见 009）。事后 Toast 已经晚了。
- 只在用户去看时才有意义的事：角标、圆点或原地状态变化，不发任何消息。

## 2. 用几个问题定案

- **谁引起的？** 用户自己、刚刚：Toast。他人、系统，或用户很久以前在别处做的：Notification。
- **要不要用户处理？** 不用：状态 Toast。可能跟一个快速的下一步（撤销、查看）：操作 Toast。要真正做决定或回复：Notification。要修复：留在那一项上。
- **能撤销吗？** 能：立即执行，用 Toast 提供撤销，不要事先确认。不能：事前确认，不是事后通知。
- **要说多少？** 几个字：Toast。一两句话，带人名、金额、地点：Notification。
- **错过了要紧吗？** 不要紧：Toast。要紧：Notification，保留到处理。
- **用户离开时工作还在跑吗？** 在他还停在页面上时结束，Toast 就够。如果他已切到别的标签页或应用，只有浏览器或系统通知（经授权）能找到他；在产品里也同时放进通知列表。
- **同时好几条？** Toast 一次一条，新的替换旧的或排队等。Notification 堆叠。

### 4A. Toast

| 项 | 数值 |
|---|---|
| 位置 | 页面顶部居中，顶栏下方 12，浮在内容上；一次一条 |
| 外形 | 高 40，圆角 16（或圆角阶梯里最近的一级）；白色表面带上下渐变 `#ffffff → #f7f9fc`；1px 描边 `rgba(214, 219, 227, 0.95)`；阴影 `0 16px 36px rgba(17, 24, 39, 0.08), 0 3px 10px rgba(17, 24, 39, 0.05)` |
| 同心 | 图标内缩 8：24 见方、圆角 8；按钮和关闭内缩 6：28 高、圆角 10 |
| 内容 | 图标 → 一行 14/20 文字 → 按钮和关闭（有的话）。图标与文字间距 8，按钮和关闭紧挨着 |
| 图标 | 完成：强调色浅底小方块上的对勾；进行中：转圈的环；撤销倒计时：逐渐变空的环，中间是剩余秒数 |
| 按钮 | 强调色文字，只在悬停时出底色 |
| 进场 | 500ms `cubic-bezier(0.25, 0.1, 0.25, 1)`：整条从上方 10px 落下、从 96% 放大、从 8px 模糊变清晰；结束前一点就完全不透明。文字和控件跟着整体走，不逐字 |
| 离场 | 220ms ease-in：上移 6px、模糊 6px、淡出 |
| 扫光 | 一道亮带扫过一次（900ms ease-out），只在「有事完成」时：状态 Toast 进场时、进度 Toast 变成结果时、撤销之后。还在等用户选择的操作 Toast 进场时不扫 |
| 原地变化 | 进度→结果、已归档→已恢复：旧的一行（文字、按钮、关闭一起）180ms 内模糊、上移 5px 离开；新的一行在 100–400ms 之间从下方 5px 模糊进入；Toast 用 380ms `cubic-bezier(0.32, 0.72, 0, 1)` 变到新宽度。只有图标单独动：旧图标缩小模糊消失，新图标从 -40° 和一半大小转进来 |
| 撤销之后 | 改动恢复，Toast 原地说明（「任务已恢复」），约 1.5 秒后离开 |
| 停留 | 状态 Toast 3–5 秒，文字长就久一些；操作 Toast 至少 5 秒；进度 Toast 工作期间一直在，完成后再 3 秒。指针悬停或焦点在 Toast 内时计时暂停 |

### 4B. Notification

| 项 | 数值 |
|---|---|
| 位置 | 右上角，顶栏下方 12，每个页面相同，浮在内容上；宽 344 |
| 卡片 | 圆角 24、内边距 12，于是头像（32，人物照片或产品 logo）和按钮（32 高、圆角 12）与卡片同心 |
| 内容 | 标题 14/20 半粗，时间在右侧；正文最多三行 13/20；最多两个按钮放右下，主按钮在最后 |
| 堆叠 | 最新的在最前。旧的裁成最前那张的高度，在它下方各露出 12，缩放 95%、90%，只露边；最多显示三张 |
| 新来一条 | 从上方 56px 滑落到堆上，560ms `cubic-bezier(0.32, 0.72, 0, 1)`，从轻微模糊变清晰；其余的同时被往下、往后推一级。被盖住的那张保留内容，直到新卡片已经在盖上来的路上，读起来是叠上去，不是替换 |
| 悬停 | 整堆展开成列表，各卡回到自身高度，间距 8，380ms 同一条曲线。列表里每张只有细描边和浅阴影，不往下一张上投影；堆叠时只有最前一张有深阴影 |
| 关闭一张 | 像 macOS：指针在卡片上时，左上角浮出一个小关闭按钮（24、圆角 10）。用卡片上的按钮处理也会移除它。移除的卡片右移 48px 并淡出（260ms），下方的用 400ms 补上空位。列表展开时最后一张下面有「全部清除」 |
| 计数 | 铃铛显示待处理的条数，页面标题也显示，后台标签页也看得到。需要决定的（安全、付款）即使从屏幕上清掉，也留在铃铛后的列表里 |

### 4C. 两者共同

- **减少动态效果**：保留状态变化和约 150ms 的淡入淡出，去掉移动、缩放和模糊。
- **读屏器**：Toast 礼貌播报（`role="status"`）；需要注意的 Notification 到达时播报一次。两者都不抢走用户当前的焦点。按钮可用键盘到达，Esc 关闭焦点所在的那一条。
- **触摸**：位置相同，支持滑动关闭；没有悬停，所以点一下展开堆叠。
- **深色**：同样的规则用在产品的深色表面上，扫光更淡。

## 5. 做用户选的

- 先列出要改的文件，等用户同意。
- 一次改一件事，每个操作原本做什么保持不变。然后检查：
  - 长短文字、缺头像、同时很多条通知、连着好几条 Toast。
  - 撤销被使用、被忽略、被关闭；进度失败；工作还在跑时离开页面。
  - 手机和桌面布局、深浅色、减少动态效果、键盘和读屏器。
  - 已有测试照样通过。
- Web：Toast 用 CSS transition 或 Web Animations API；堆叠要量每张卡的高度，transform 和 height 一起动画。Sonner（React）有类似的堆叠可以改用，但加之前先问。iOS、Android、Flutter 用平台自己的动画工具和同样的数值；要在应用外找到用户的消息，用系统通知。

## 6. 实现要点（demo 的做法）

- **Toast 槽位**：一个常驻的 `role="status"` 容器横跨顶部、`justify-content: center`，Toast 放在里面。居中交给容器，Toast 自己的 transform 留给进场、离场动画；变宽时自然从中间向两边长。
- **一次一条**：新 Toast 来时旧的先离场（220ms），新的晚约 140ms 进场，避免两层模糊叠在一起。被替换的操作 Toast 视为「忽略」，改动保留。
- **进场**用 WAAPI 关键帧：`{opacity:0, transform:'translateY(-10px) scale(.96)', filter:'blur(8px)'}` → 中间一帧只写 `{opacity:1, offset:.7}` → `{transform:'none', filter:'blur(0)'}`，整段 500ms 用同一条曲线，透明度在 70% 处已到 1。
- **原地变化**：克隆旧的那一行，绝对定位在原处做离场；真实的那一行换成新内容做进场（`delay 100ms, duration 300ms, fill: backwards`）。先量旧宽度，换内容后 `width:auto` 量新宽度，对 `width` 做 380ms 动画，播完清掉内联宽度。Toast `overflow: hidden`、那一行 `white-space: nowrap; flex: none`，宽度过渡中多出的文字被裁掉而不是换行。图标盒里放两层，旧层缩到 0.5 模糊淡出，新层从 `rotate(-40deg) scale(.5)` 转进来。
- **同心**：Toast 有 1px 描边，内边距要减掉它（左 7、右 5），图标外沿才是 8、按钮外沿才是 6。
- **扫光**放在内容下面：一层 `inset:0` 的容器里一条斜向渐变带，从 -100% 平移到 +100%。白色表面上纯白带看不见，带子两侧加一点强调色（约 8–10% 透明度），中间是白色高光；深色下用 `rgba(255,255,255,.07)` 左右。
- **计时器**：自己记剩余时间，`pointerenter` / `focusin` 暂停，`pointerleave` / `focusout`（焦点和指针都不在里面时）继续。倒计时环用 WAAPI 动画 `stroke-dashoffset`，和计时器一起 `pause()` / `play()`；中间的秒数按剩余时间 `Math.ceil` 显示。
- **进度失败**：Toast 原地变成「上传失败」（不扫光），附「查看」把焦点带到那一行；那一行保持错误状态和「重试」，直到修好。工作结束时如果 `document.hidden`，同时往通知列表里放一条。
- **通知堆叠**：每张卡是一个外层（负责 transform 和关闭按钮）+ 一个 `overflow:hidden` 的盒子（负责高度和圆角）+ 内容。布局函数算出每张的 `y`、`scale`、`height`、内容透明度，用类似 015 的 `go()`：先读计算样式里的当前值、取消旧动画、写入终值、再从当前值动画过去，所以中途悬停、新来、关闭都能接上。
  - 收起：第 i 张 `height = 最前一张高度`、`translateY(12i) scale(1 - .05i)`、`transform-origin: 50% 100%`，底边正好各露 12。
  - 展开：`y = 前面各张高度之和 + 8i`、`scale(1)`、各自高度。
  - 新来：新卡从 `translateY(-56px)`、透明、`blur(6px)` 落到 0；被盖住的那张内容延迟约 140ms 再淡出。
- **最多三张**：超出的从屏幕上退下，但仍在铃铛列表里计数。
- **放不下时**：窗口矮、展开的列表加「全部清除」超出底部时，让通知区域在展开状态下滚动（`overflow-y: auto`，收起时恢复 `visible` 并把 `scrollTop` 归零）。区域四周比卡片多留 8 / 4，左上角的关闭按钮和阴影才不会被滚动容器裁掉。
- **撤销要取消进行中的离场**：归档时行在做收起动画，用户在动画播完前点撤销，必须先 `cancel()` 那段动画；否则它的结束回调晚到，又把刚恢复的行藏起来。
- **计数**：清掉普通通知会从列表移除；需要决定的只从屏幕移除。`document.title` 前加 `(n) `。
- **滑动关闭**：在卡片上（不在按钮上）水平拖动，用 CSS 独立属性 `translate` 跟手，不和布局用的 `transform` 打架；超过约 64px 松手就继续向右离场，否则弹回。
- **减少动态效果**：Toast 只做 150ms 透明度；变宽直接跳到新宽度；不扫光。通知直接放到新位置，只淡入淡出。系统开启减少动态效果时 `base.css` 会把 CSS transition 压到 0.01ms，所以这些淡入淡出都用 WAAPI 做。
- 参考实现见 `assets/016-toast-notification.html`。

## 常见错误

- 用户自己的操作发 Notification，或者别人发来的消息只发一个 Toast，几秒后找不回来。
- 不可撤销的删除只在事后弹一个「已删除」Toast；可撤销的操作反而先弹确认框。
- 失败只发一个会消失的 Toast，那一项上看不出出了问题。
- 表单校验错误用 Toast 报，用户还得记住是哪个字段。
- 操作 Toast 停留太短、看不到剩余时间，或悬停时还在倒数。
- 进度 Toast 完成后另起一条新的结果 Toast，而不是原地变成结果。
- 每条 Toast 都扫光，或者还在等用户选择的操作 Toast 也扫光。
- 连着几条 Toast 叠在一起；或者 Notification 新的一条直接替换旧的。
- 堆叠时每张卡都带深阴影，层层投影发脏；展开后阴影压到下一张上。
- 堆叠只动 transform、不动高度，裁切后的卡露出底下一截内容。
- 新通知、Toast 抢走焦点；读屏器听不到 Toast，或每次重排都重新播报一遍。
- 减少动态效果下还在移动、缩放、模糊。
