# 005 · 更灵动的拖拽排序

原帖：https://x.com/Kubai087/status/2115823717024735708

## 原理

拖拽排序时，让落点两侧的元素轻轻让开，并且由近及远依次启动，动作更像真实世界里的推挤。适用于横排（Dock、标签栏）和竖排（列表、看板）。复用项目已有的拖拽工具，只改手感。

## 规则

1. 光标：可拖元素上显示手指（pointer），拖动中显示抓手（grabbing）。
2. 抬起：被拖元素跟着指针走，并离开列表，绝不挡住落点。横排时浮到行的上方；竖排时拉到一侧并缩小到约 90%。原位收起。
3. 落点提示：在将要落下的缝里画一条很淡的细线（横排为竖线，竖排为横线），约为文字色的 15%。出现时从中间展开，之后滑到每个新的缝。落回原位时不画线。
4. 让位涟漪：线两侧的元素向外让开。从线开始计数，n = 0 是紧挨着线的那个：
   - 位移 = A × 0.7ⁿ（图标约 A = 10px，卡片约 8px）
   - 延迟 = 24ms × n
   - 用一个几乎不过冲的快弹簧，约 0.25s 停稳。离得越近，动得越早、越多，推力像涟漪一样散开。
5. 落下：元素进入缝里，其余元素各自弹到新位置。按 Esc 或拖出列表就取消，全部弹回原位。
6. 每种动作用自己的曲线：跟手的用直接跟随，抬起用一个小的弹出，落位用弹簧；不要全都用同一个 ease-out。

## 实现要点

- 只用 transform 移动元素，不改布局。拖动过程中用「原位收起后的基准位置」算落点和让位，落下时再一次性改 DOM 顺序。
- 落位用 FLIP：记录改顺序前的位置 → 改顺序 → 清掉 transform 量新位置 → 写入反向位移 → 下一帧移除，让弹簧过渡接管。
- 让位的错峰直接用 `transition-delay: 24ms × n`，弹簧可以用 `cubic-bezier(.3, 1.25, .5, 1)` 约 250ms 近似。
- 键盘也能排序（例如聚焦后按方向键移动一格），同样走 FLIP。
- 减弱动态效果时只保留插入线，不做让位。
- 参考实现见 `assets/005-drag-reorder.html`（通用的 `sortable(list, { axis, A })`）。

## 常见错误

- 被拖元素压在落点上，用户看不到会落在哪。
- 所有元素同时、同幅度平移，像整体滑动而不是推挤。
- 拖动过程中实时改 DOM 顺序，造成布局抖动。
- 落回原位时还显示插入线。

## 验收

- [ ] 横排和竖排都能拖，落点线始终可见且不在原位出现。
- [ ] 最靠近线的元素最先动、动得最多，往外依次减弱。
- [ ] Esc 和拖出列表都能取消并弹回。
- [ ] 键盘可以完成排序。
