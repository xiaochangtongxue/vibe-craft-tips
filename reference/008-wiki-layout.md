# 008 · Wiki / 帮助中心的框架与布局

原帖：https://x.com/Kubai087/status/2116911391437443471

## 原理

产品变复杂、或官网需要大量 SEO 文章时，一套可靠的 Wiki 页面既能快速解答用户疑问，也能带来搜索流量。要同时照顾 PC 和手机。

## 范围

只改页眉、页面列表（侧栏）、本页大纲和文末这几块的位置、滚动和响应方式；保留内容、文案、颜色和字体。改在共享的文档布局上，让每一页继承结果。

## 规则

1. 导航栏：LOGO（回官网）+ 关键页面的下拉菜单 + 核心 CTA 按钮，滚动时吸顶。Safari 等浏览器会按导航栏颜色给地址栏着色，导航栏背景要和品牌色协调。
2. 章节导航（侧栏）：高度独立、和正文分开滚动，超出部分上下截断。截断的边缘一定要加渐变遮罩，让用户知道上下还有内容；再配一个居中的箭头按钮方便点击。当前页在列表里高亮并滚到可见位置。
3. 本页大纲：吸顶，随正文滚动高亮当前小节，点击平滑滚到对应标题（标题留出吸顶导航的 `scroll-margin-top`）。
4. 文末引导：在解答问题的文章底部放社群、社媒等转化入口，卡片样式贴近正文组件，看起来是内容的一部分，而不是广告。再放上一篇 / 下一篇。
5. 页脚：高度超过半屏，用好看的背景撑起来，吸引用户滑到底并停留；同时放足够有用的信息（产品、资源、社区链接、联系方式），真正帮到用户才不招人反感。
6. 移动端：屏幕窄，侧栏和大纲收起；底部常驻一个章节栏，显示当前所在章节，点开后用满屏菜单列出全部章节，一行一个，方便点。

## 实现要点

- 三栏网格：侧栏约 196px、正文 `minmax(0, 1fr)`（行宽约 66ch）、大纲约 160px；窄屏切成单栏。用容器查询（`container-type: inline-size`）比视口断点更稳，嵌在任意宽度的容器里都能对。
- 侧栏截断遮罩用 `mask-image` 的上下渐变，按滚动位置分别开关上、下遮罩和箭头。
- 移动端章节栏用 `position: sticky; bottom: 0`，满屏菜单是一个可关闭的对话框（有关闭按钮、焦点进入和返回）。
- 参考实现见 `assets/008-wiki-layout.html`（可切换 PC / 移动端）。

## 验收

- [ ] 导航吸顶，下拉菜单可用键盘打开。
- [ ] 侧栏单独滚动，截断处有渐变和箭头，滚到顶 / 底时对应的遮罩和箭头消失。
- [ ] 大纲高亮跟随正文滚动。
- [ ] 文末有贴近正文风格的转化入口，页脚超过半屏。
- [ ] 手机上底部章节栏可以打开满屏章节菜单。
