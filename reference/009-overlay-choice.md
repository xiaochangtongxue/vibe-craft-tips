# 009 · 提示框、跟随气泡、就地确认、抽屉与弹窗怎么选

原帖：https://x.com/Kubai087/status/2117314098165862612

## 决策规则

### 补充信息

- Tooltip（提示框）：为光标指着的内容补充文字，常见于被截断的长文本。里面只放文字，不放操作。
- Popover（点击打开的气泡）：需要放操作时用它，例如「⋯」更多菜单。
- Cursor tip（跟随气泡）：在一块区域内持续提供信息，光标移入才出现并跟着光标走，常见于图表和相对独立的元素。
- 手机上没有悬停，以上都改成点击显示。

### 确认

- 能撤销的操作：直接执行，再留一个「撤销」入口（提示条里的撤销按钮）。不要弹确认。
- 不可逆的操作才需要二次确认：大多数情况用就地确认（Popconfirm），路径短、不打扰。
- 影响大、批量的操作，或必须让用户停下来的，再用弹窗（Dialog）。

### 表单放在哪

- 表单短、不需要参照界面上的其他信息：弹窗。
- 表单长、需要对照界面内容，或想更好地利用横向空间：抽屉（Drawer）。
- 本身就是主要任务的：独立页面。

## 实现要点

- Tooltip 有约 350ms 的悬停延时，键盘聚焦时也显示，`role="tooltip"`；靠近视口边缘时翻转位置。
- Popover 打开后焦点进入第一项，Esc 和点击外部关闭并把焦点还给触发按钮。
- 撤销提示条约 5 秒自动消失，撤销后恢复到原来的位置。
- Popconfirm 锚定在触发按钮附近，默认聚焦「取消」，确认按钮用危险色并写明后果（「删除后无法恢复」）。
- Dialog 用原生 `<dialog>` 的 `showModal()`，确认按钮写清动作和数量（「清空 3 个文件」）；每次打开前重置 `returnValue`，避免 Esc 关闭时沿用上一次的结果。
- 抽屉从右侧滑入，宽度不超过容器的约 78%，左侧内容保持可见。
- 参考实现见 `assets/009-overlay-choice.html`。

## 选型速查（给 Agent）

改造前先把界面里每一个浮层列出来，逐个回答三个问题再决定组件：

1. 里面有没有可点击的操作？有 → Popover 而不是 Tooltip。
2. 这个操作能不能撤销？能 → 直接执行 + 撤销；不能 → Popconfirm；批量或影响大 → Dialog。
3. 表单多长、要不要对照界面？短 → Dialog；长或要对照 → Drawer；主任务 → 独立页面。

## 验收

- [ ] 没有把操作按钮塞进 Tooltip。
- [ ] 可撤销的操作没有多余的确认弹窗。
- [ ] 不可逆的单个操作是就地确认，批量操作是弹窗，文案写明后果。
- [ ] 手机上所有悬停类浮层都能点击打开。
