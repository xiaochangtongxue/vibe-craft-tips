# 017 · 等待状态：什么都不显示、Spinner、骨架、进度、乐观更新、流式回答

原帖：https://x.com/Kubai087/status/2121449185014845794（第 0–6 节判断规则和数值来自原帖随附的 Prompt）

## 原理

等待躲不掉，要决定的是怎么告诉用户，有时甚至应该先给结果、再按服务器的回答更正。按「等多久、知不知道布局、能不能数、会不会失败、能不能退回」选：

| 情况 | 用什么 |
|---|---|
| 300ms 以内 | 不显示单独的加载状态，结果本身就是反馈（否则一闪而过） |
| 一个操作、几秒内完成、时长未知 | 按钮原地的 Spinner，结束后 Toast 说结果 |
| 布局已知的内容 | 骨架，内容到达后原位替换 |
| 可以计数的长任务 | 进度：在做什么、到哪了、还要多久，结束后原地变成结果 |
| 大概率成功、容易退回 | 乐观更新：先显示结果，后台保存，失败就退回、说明原因、给重试 |
| AI 回答等分段到达的结果 | 先列步骤，再边到边写 |
| 用户不需要看见的等待 | 什么都不显示，或固定位置的安静状态 |

这一期的 Prompt 是「先判断、再建议、只改用户同意的」：先找出产品里所有等待的地方，逐个判断该用哪种，列表给用户选，选了再动手。

## 范围

改用户的产品，不做 demo：用户的代码、技术栈、组件、token、动效数值和文案风格。不经询问不加依赖、不加数据库类库、不引入新的视觉模式。下面所有数值都是起点。

## 0. 先读产品

- 找出所有用户会等的地方：页面和路由加载、列表和表格、搜索和筛选、调用服务器的按钮（保存、发送、同步、删除）、上传、导入导出、后台任务、AI 调用。
- 每一处记下：由什么触发；通常要多久（实测，或按调用估：有缓存、一次请求、几次请求、一个任务）；等待时显示什么（spinner、骨架、什么都没有、挡住页面的遮罩）；数据到达时布局会不会动；用户能不能继续干别的；失败时怎样；能不能取消。
- 找到共用的部件：spinner、骨架、进度组件，数据层（fetch 封装、React Query、SWR、Apollo、store），以及全局的加载条或遮罩。
- 继续之前，用几行告诉用户看到了什么。

## 1. 七种等待

**a. 300ms 以内**：不显示单独的加载状态（不要 spinner、骨架、进度条），出现又在 300ms 内消失看起来就是闪了一下。唯一例外是图标本身就代表这个操作的按钮，它从按下就开始转（见 b）。结果就是反馈：结果出现在用户正看着的地方，就不需要别的；不在（同步、复制、屏幕外的保存），用一个短 Toast 确认。

**b. 一个操作的短等待，时长未知（约 0.3–3s）**：在用户操作的地方显示，按钮的文字和宽度不变。
- 按钮图标本身就代表这个操作（同步、刷新）：从按下就转，即使回答瞬间就到也至少转满一圈，一直转到回答到达，总是停在整圈上。
- 否则图标变成 spinner：300ms 后才出现，出现后至少保留 500ms。
- 进行中挡住第二次点击，但绝不把整页变灰。完成后按钮恢复原样，一个短 Toast 说结果（「已同步，1 个任务有更新」）：顶部居中、几个字、约 3 秒后消失。

**c. 布局已知的内容（页面、列表、卡片、表格）**：骨架。
- 不依赖数据的部分立刻显示：标题、标签页、筛选、表头。
- 300ms 后为其余部分画骨架形状，用真实的尺寸和位置：同样的行高、同样的头像大小；线条比文字略短，长度略有变化。
- 一道亮带每 1.2s 一起扫过整个列表。
- 数据到达时，真实的行占据同样的位置，自上而下，每行 200ms 淡入、间隔 40ms。什么都不跳。返回的行比骨架少，多出的形状淡出。
- 绝不用空白页正中一个孤零零的 spinner 代替。

**d. 可以计数的长任务（上传、导入、导出、批处理，超过约 3s）**：进度。
- 说清在做什么、到哪了（计数或百分比，加一条进度条），有一秒的数据可以估算后显示剩余时间；在那之前显示「正在估算…」。
- 用户会接着干别的时（导入、导出、批处理），放在右上角的通知里：不占页面，每一页都在，保留到处理。只关乎某一项的工作可以显示在那一项的位置上，同样大小，页面上什么都不动。
- 页面保持可用，提供取消。能脱离用户继续的，就让它在后台跑，完成时告诉用户。
- 工作跑了 300–500ms 之后才显示；在那之前就完成的，只给结果。
- 结束时原地变成结果，点击打开它。
- 无法计数的长任务：说出当前阶段（正在连接、正在处理 3 个文件），而不是一个转不停的 spinner；约 10s 后说明比平常慢，并提供转到后台继续。

**e. 几乎总能成功、又容易退回的操作（标为完成、点赞、重命名、排序、移动、加评论）**：乐观更新。
- 不等服务器回答就显示结果，在它出现的每个地方都改（对勾、状态、合计），后台保存。在这一项上一个固定的位置安静地说正在保存（「保存中」，然后「已保存」，过一会儿淡出），绝不在改动本身上盖一个 spinner。
- 保存失败：把改动的每一部分都退回，在这一项上用几个字说原因（「没能保存」），在原来「保存中」的位置提供重试。保留用户输入的内容。
- 不用于：付款、永久删除、发送给别人的东西，以及任何不能悄悄退回的操作。

**f. AI 回答和其他分段到达的结果**：
- 先用步骤说正在做什么（读取 4 个任务、查看 3 个日程、撰写总结），每一步完成变成对勾。
- 然后边到边写，每段文字在下一段开始时从轻微模糊中淡入，最后一段后面跟一个光标。
- 从一开始就给回答留好位置（卡片按最终大小，或者一个只向下增长的最小高度），写的过程中页面不动。
- 结束时显示复制和重试。只有回答经常很长时才提供停止。
- 争取 1–2s 内出现第一批字；做不到时，步骤必须一直在动。

**g. 用户不需要看见的等待（预取、保存草稿、后台同步）**：什么都不显示，或在固定位置一个安静的状态（已保存）。绝不为它们挡住页面。

## 2. 各种等待都要遵守

- **阈值**：300ms 以内除了按钮自己的图标转动，什么都不显示；300ms–1s 用 spinner 或骨架；1–10s 用骨架，或说明在做什么的进度；超过 10s 用进度、剩余时间和退出的办法。在慢速移动网络上测，不要在 localhost 上测。
- **延迟和最短时长**：300ms 后才出现的东西，至少保留 500ms。写一个辅助函数，到处都用它。
- **数据到达时布局不动**：预留空间（真实尺寸的骨架、最小高度、固定的图片比例）。
- **一次等待一个指示**：绝不同时出现按钮上的 spinner、页面遮罩和顶部进度条。
- **保留已知的**：刷新时继续显示旧数据，加一个安静的刷新状态，而不是换回骨架。
- **失败留在出事的地方**：说什么失败了、该怎么办，提供重试。会消失的 Toast 不够用于用户必须修复的事。
- **减少动态效果**：每个状态都保留；去掉移动的亮带和旋转，改用柔和的透明度呼吸，或者什么都不用。
- **无障碍**：正在加载的区域设 `aria-busy`，完成和失败用礼貌的 live region 播报，焦点留在原处，忙碌中的按钮仍可用键盘到达。

## 4. 样子（默认值，按用户的设计调整）

| 部件 | 数值 |
|---|---|
| Spinner | 用户图标集里的加载图标（或淡色轨道上的一段圆环），12–16px，每 0.9s 一圈，强调色或文字色 |
| 按钮里转自己的图标 | 前 18% 加速、后 18% 减速，起停都是静止的：最少一圈 640ms；等得更久就以约 600°/s 持续转（三圈约 1.7s），总是停在整圈上 |
| 按钮里换成 spinner | 图标在 180ms 内带一点模糊和缩放交叉淡化成 spinner；文字和宽度不变 |
| Toast | 40px 高、圆角 16，浅底小方块上的对勾加几个字，内容区顶部居中；500ms 从上方 10px、轻微模糊落下，约 3s 后离开（同 016） |
| 骨架 | 形状用凸起灰：白底上 `rgb(240 240 242)`，深色上白色 8%；线条圆角 6px，图片用圆形；14px 文字对应 12px 高的线条。亮带白色 75%、宽 320px，一次扫过整个列表 |
| 通知里的进度 | 宽 344、圆角 24、内边距 14（右侧 16），右上角。32px 图标块与旁边文字垂直居中，里面是 18px 双色填充的文件类型图标；标题（正在导入 tasks.csv）；计数和剩余时间一行（1,240 行中的 568 行 · 约 2 秒）；4px 进度条，强调色在 10% 强调色的轨道上。没有按钮行：点卡片打开它说的东西，悬停时出现的关闭标记就是取消 |
| 进度通知的进场 | 从上方 56px、4px 模糊、96% 大小落到页面上，420ms |
| 进度通知完成 | 同一张卡原地变化：旧文字 160ms 模糊离开，新文字 420ms 模糊进入（已导入 1,240 个任务 / 已加入待办。）；进度条收起；图标块变成实心绿色，里面一个粗白对勾，同样 18px。之后保留到被打开或关闭 |
| 乐观更新 | 任务图标的位置上一个 20px 复选框，悬停时出现，勾选后填满绿色；合计数字 320ms 滚动到新值；「保存中」带 12px spinner，然后「已保存」带对勾，在这一行最后一列的开头，12px 灰字 |
| 乐观更新失败 | 这一行左右摇 6px、两次、共 360ms；红色原因占据这一行计数的位置，重试占据「保存中」的位置，直到修好 |
| AI 回答 | 步骤 13px，16px spinner 变成对勾；回答 15/24；光标 2px 宽、强调色；最后是重试和复制 |

## 5. 按平台实现（按用户的版本核对，优先用产品已有的）

- **Web**：延迟和最短时长写成一个 hook 或辅助函数，例如 `useDelayedFlag(loading, 300, 500)`。React：Suspense 配骨架 fallback，`startTransition` 在新内容加载时保留旧内容，`useOptimistic` 或 mutation 的 `onMutate` 加回滚；React Query、SWR 在重新请求时保留上一次的数据。流式回答用 `fetch` 的 `ReadableStream` 读取，或 AI SDK 的 `useChat`。亮带画成固定在列表上的一条渐变，用 `background-position` 移动，`prefers-reduced-motion` 下停掉。
- **iOS**：骨架用 `.redacted(reason: .placeholder)`，进度用 `ProgressView`，取消用 Task 取消，乐观更新在 view model 里做并带回滚，流式文字用 `AsyncSequence`。
- **Android**：Compose 里在占位形状上用 shimmer brush，`LinearProgressIndicator` 传值，列表用 Paging 的 `LoadState`，乐观状态放在 ViewModel 里并带回滚，流式文字用 `Flow`。
- **Flutter**：真实控件作占位、上面盖 shimmer（或 Skeletonizer），`LinearProgressIndicator(value:)`，流式文字用 `Stream`。
- **Rust 和其他原生桌面（egui、iced、GPUI、Tauri）**：同样的状态放在 UI 模型里，300 和 500ms 的计时器放在 update 循环里。

## 6. 实现要点（demo 的做法）

- **一个延迟辅助函数**：`delayed(show, hide)` 300ms 后才调用 `show`，返回 `end()`；`end()` 在没显示过时直接结束，显示过就补足 500ms 再 `hide`。按钮 spinner、骨架都用它。
- **按钮转自己的图标**：用 rAF 积分角度，不用 CSS 无限动画（停不到整圈上）。按下时速度在 115ms 内线性升到 680°/s（单圈 640ms 里前后各 18%），回答到达后算出「当前角度 + 减速距离」之后的下一个整圈作为终点，巡航到剩余距离等于减速距离时开始线性减速，正好停在终点。回答再快也至少一圈。
- **按钮里换成 spinner**：图标和 spinner 叠在同一个 16px 格子里，180ms 交叉淡化，带 `blur(2px)` 和 `scale(.6)`；按钮文字不动、宽度不变。忙碌时用 `aria-disabled` 挡第二次点击，不用 `disabled`，键盘还能到达。
- **骨架亮带**：用 `@property` 注册一个继承的长度变量 `--t017-band`，在列表上用 WAAPI 从 -320px 动到列表宽度，1.2s 一轮；每个形状的背景是「320px 宽的白色渐变 + 凸起灰」，`background-position-x: calc(var(--t017-band) - 形状在列表里的 left)`。所有形状共用列表的坐标，看起来是一道光扫过整个列表；Safari 也不依赖 `background-attachment: fixed`。
- **骨架画几行**：按一页的条数画（demo 里是 6），不要按「填满可见区域」算。按可见区域画出 4 行、数据回来 6 行，列表到了还会往下长；按页数画，少了的多出形状淡出就行。
- **骨架换成真实行**：每一行是一个固定高度的格子，骨架和真实内容叠在同一个 grid 区域；真实内容 200ms 淡入，骨架同时淡出，第 i 行延迟 40i ms。多出的骨架行淡出后移除。
- **刷新保留旧数据**：第二次进入或点刷新时，旧的行留着，标题旁一个安静的「正在刷新」，回来后原地更新。只有缓存为空时才画骨架。
- **进度通知**：卡片从 `translateY(-56px) scale(.96)`、`blur(4px)` 落到原位（420ms，`cubic-bezier(.32,.72,0,1)`）；剩余时间按「已用时间 / 已完成比例」估算，满 1s 前显示「正在估算…」。完成时克隆旧的文字块原地模糊离开（160ms），新文字块从模糊进入（420ms），进度条对高度和外边距做动画收起，图标块换成绿色实心加对勾。
- **乐观勾选**：点下去立刻改复选框、状态、表头合计，再发请求。合计数字用上下两层，旧值上移淡出、新值从下方进入，320ms。失败时把三处都退回，行做 `translateX` 0 → 6 → -6 → 6 → -6 → 0 的 360ms 摇动，原因替换计数，重试替换「保存中」。
- **流式回答**：卡片一开始就有最小高度。步骤逐个变成对勾后开始写字，每段新文字用 WAAPI 从 `blur(4px)`、透明淡入，光标是跟在最后一段后面的 2px 竖条。
- **减少动态效果**：图标不转，改为透明度呼吸；骨架不扫光，形状做柔和的透明度呼吸；各种进场只做 150ms 淡入。
- 参考实现见 `assets/017-loading-states.html`。

## 常见错误

- 一律加 spinner：很快的请求也闪一下；或者 300ms 刚过就出现、马上又消失。
- 空白页正中一个 spinner，数据到了整页从上往下跳。
- 骨架尺寸和真实内容不一样，替换时行高、头像大小一变，页面还是跳。
- 每个骨架形状各自扫光，几十道光此起彼伏。
- 刷新时把已有内容换回骨架，用户刚读到的东西没了。
- 按钮转圈时文字换成「加载中…」，按钮宽度变了；或者整页变灰、挡住所有操作。
- 自己的图标用 CSS 无限旋转，回答一到就停在半圈上，或者快请求只抖了一下。
- 同一个等待既有按钮 spinner、又有页面遮罩、又有顶部进度条。
- 长任务一个转不停的 spinner，不说在做什么、还要多久，也不能取消或转到后台。
- 乐观更新失败只弹一个会消失的 Toast，改动没退回，或者退回了却不说为什么。
- 对付款、永久删除、发给别人的消息做乐观更新。
- 流式回答一边写一边把页面往下推，或者第一批字之前什么都不显示。
- 减少动态效果下亮带还在扫、图标还在转。
