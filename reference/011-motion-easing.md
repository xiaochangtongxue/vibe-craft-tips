# 011 · 选对动画的节奏（缓动曲线与时长）

原帖：https://x.com/Kubai087/status/2118143759984803898

## 原理

动画的节奏由速度曲线决定。曲线越陡，速度变化越剧烈，看起来就越「快」。曲线要按元素的角色来选：入场、退场、原地换位、确认、松手归位，各用一种。整个产品同一种角色用同一条曲线，不逐个组件手调。

## 范围

保留每个动画「动什么、动多远、由什么触发」，只改它随时间怎么动；时长明显不对时一并改时长。

## 第 0 步：先盘点

- 找出所有过渡和动画，包括 CSS transition / keyframes、动画库（Framer Motion、GSAP、Web Animations API）、手写的 requestAnimationFrame 循环。逐个列出组件、触发方式、时长和曲线。
- 重点标出三类：停在 CSS 默认 `ease` 上的；会移动的东西用了 `linear` 的；出现时用了 `ease-in` 的。

## 曲线 token

在其他动效 token 旁边一次性定义，之后只用这些：

| token | 值 | 用在 |
|---|---|---|
| `--ease-out` | `cubic-bezier(0, 0, .58, 1)` | 所有入场：toast、菜单、气泡、弹窗、抽屉 |
| `--ease-out-strong` | `cubic-bezier(.22, 1, .36, 1)` | 点击后马上落位的小部件：图标、文字、选中的胶囊。最跟手 |
| `--ease-in` | `cubic-bezier(.42, 0, 1, 1)` | 只用于退场：toast 超时消失、弹窗或抽屉关闭、菜单收起、列表项被划走。用在入场会先显得迟钝、再「咚」地停下 |
| `--ease-in-out` | `cubic-bezier(.42, 0, .58, 1)` | 一直在屏幕上、只换位置或尺寸的东西：标签/分段控件下的指示条、轮播翻页、排序时让位、侧栏调宽、平滑滚动到锚点。不用于入场，慢启动像卡顿 |
| `--ease-overshoot` | `cubic-bezier(.34, 1.56, .64, 1)` | 冲过约 10% 再退回。小而俏皮的确认：勾选、点赞、角标数字弹出、开关滑块落位。不用在弹窗、抽屉或超过约 64px 的元素上，也不用在每天反复操作的动作上 |
| `--ease-spring` | `linear(0, .32, .78, 1.04, 1.09, 1.06, 1.02, 1, .99, .99, 1)` | 拖动或滑动后松手的东西，像实物一样停稳：底部面板弹开或回弹、半划卡片归位、下拉刷新回弹、排序项落位 |
| `linear` | — | 只给「在跑」而不是「在动」的东西：加载圈、进度条、跑马灯 |

- 动画库自带弹簧时优先用库的弹簧，并传入松手速度；没有时才用 `--ease-spring`。不支持 `linear()` 的环境退回 `--ease-out-strong`。
- CSS 默认的 `ease` 不算一种选择，凡是没写曲线的地方都换掉。

## 时长 token

| 尺寸 | 入场 | 退场 |
|---|---|---|
| 小（toast、tooltip、菜单、勾选） | 150–250ms | 120–200ms |
| 中（弹窗、带内容的气泡、抽屉） | 250–350ms | 略短于入场 |
| 大或全屏（sheet、页面转场） | 350–500ms，再长就慢了 | 略短于入场 |

- 退场永远比入场短。
- Spring 和 Overshoot 约为普通时长的 1.5 倍，回弹需要时间。
- 时长也做成 token 放在曲线旁边：`--duration-sm` / `-md` / `-lg`。

## 按角色套用

- 入场：`--ease-out`，从它所属的方向来（toast 从顶边、菜单从触发按钮），距离短（8–24px），从 96% 长大，透明度比位移先到。toast 可以加约 8px 的模糊、落位时清晰，是个不错的点缀。
- 退场：`--ease-in`，原路返回，时长更短。
- 屏幕内换位：`--ease-in-out`。
- 刚出现的容器里的部件（图标、文字、数字）可以晚 100–200ms 用 `--ease-out-strong` 跟上，分步落位，而不是一起到。
- 手势：指针或手指移动时 1:1 跟随，不加任何缓动；松手后用弹簧收尾，库支持时传入松手速度。
- 悬停和按下：100–150ms `--ease-out`。悬停时绝不动画布局。
- 只动画 `transform` 和 `opacity`（`filter` 少用）；不要动画 `top`、`left`、`width`、`height`，它们每帧都会重新布局和重绘。

## 一致性与无障碍

- 全产品一个角色一条曲线。
- 尊重 `prefers-reduced-motion`：保留透明度变化，去掉位移和缩放，弹簧和回弹改成普通的 150ms 淡入淡出。
- 不让用户等动画：动画不阻塞输入；新操作从动画当前所在的位置打断旧动画，不先跳回起点。

## 实现要点

- 状态用 CSS transition 写时，入场和退场的曲线、时长分别写在两个状态上：显示态写 `--ease-out` + 入场时长，隐藏态写 `--ease-in` + 退场时长（过渡用的是目标状态上的值）。
- 中途接住拖动：`pointerdown` 时先读出当前位置（`new DOMMatrix(getComputedStyle(el).transform)`），再去掉过渡类，并把这个位置写回，避免跳变。
- 松手判定：按最后一段的速度判断，超过约 0.3px/ms 就沿速度方向收，否则就近收；停住超过约 80ms 再松手，速度按 0 算。
- 参考实现见 `assets/011-motion-easing.html`。上半部分是曲线实验台，用残影显示每条曲线的速度分布；下半部分是 toast、标签指示条加轮播、点赞加勾选、底部面板、进度条五个场景，可以切到「全用默认 ease」和「用反了」对比，也可以慢放 3 倍。

## 交付

1. 先列出找到的每个动画：当前曲线和时长，以及准备给它的角色和曲线。
2. 再加 token、逐个切换，列出改动的每个文件。
3. 不改动画对象、幅度和触发方式。某个动画说不清是什么角色时，先问用户。

## 常见错误

- 没写曲线，全部停在默认 `ease`。
- 入场用 `ease-in`：先迟钝后急停。
- 指示条、轮播用 `linear` 或 `ease-out`，起步突兀。
- 大面板加回弹，看起来晃、不稳重。
- 拖动过程中也套缓动，手和元素脱节。
- 退场和入场一样长，关闭显得拖沓。

## 验收

- [ ] 代码里不再有未指定曲线的过渡，也没有散落的 cubic-bezier 魔法数字。
- [ ] 入场 ease-out、退场 ease-in 且更短，换位 ease-in-out。
- [ ] Overshoot 只用在 64px 以内的小确认上；Spring 只用在松手归位上。
- [ ] 拖动时 1:1 跟手，中途再按能从当前位置接住。
- [ ] 开启减弱动态效果后只剩淡入淡出。
