# 015 · 连续性：点到的元素直接变成下一个状态

原帖：https://x.com/Kubai087/status/2120320609255043510（第 0–6 节数值来自原帖随附的 Prompt）

## 原理

界面状态变化时，用户点到的元素不消失再重新出现，而是直接过渡成下一个状态，让人始终清楚自己从哪里来、现在在哪里。原帖用 iOS 里七个常见场景演示：

| 场景 | 连续的做法 |
|---|---|
| 导航 | 行标题延续为页面标题，原页面标题收成返回按钮；滚动时大标题收进顶栏 |
| 卡片 | 卡片展开为正文，图片延展为头图；下拉时沿原路收回 |
| 播放条 | 迷你播放条展开为播放页，封面、标题、按钮各归其位 |
| 搜索 | 搜索框移到顶部，匹配项随输入上移，其余淡出 |
| 图表 | 数据卡片展开为图表，卡片里的小柱延续为图表的柱 |
| 菜单 | 菜单从按钮原位展开；新增项落入首位，其余依次后移 |
| 标签栏 | 选中胶囊先伸展，再落位 |

这一期的 Prompt 是「先诊断、再建议、只做用户选的」：先读产品，列出最值得做连续性的跳变点，用户挑了再动手。

## 范围

改用户的产品，不做 demo：用户的代码、技术栈、组件、token、布局。每个操作做什么、每屏显示什么、东西最后在哪里，都不变；只改一个状态怎么变成下一个。不照搬演示场景（手机框、背景、样例内容、字体）。新增依赖或改路由先问。数值都是起点；手机和桌面都适用，差别见第 3 节。

## 0. 先读产品

- 屏幕、路由、面板、sheet、对话框、菜单、列表，以及彼此怎么打开：导航栈或路由、模态和 sheet 的弹出方式、popover 和菜单组件、列表和网格组件。
- 现在什么在动、怎么动：CSS transition、View Transitions API、Motion / Framer Motion、GSAP、SwiftUI 或 UIKit 转场、Compose 动画、Flutter Hero 或隐式动画。记下动效 token（时长、曲线、弹簧）和减少动态效果的处理，复用它们。
- 有哪些布局（手机、平板、桌面窗口、分栏）和各自的输入（触摸、鼠标、键盘）。
- 继续之前，用几行告诉用户看到了什么。

## 1. 找什么：跳变的八种形态（越常见越靠前）

跳变：用户操作一个元素，下一个状态凭空出现——硬切、整屏交叉淡化，或者从一个无关的边滑进来。

- **a. 行 → 详情页**：行标题长成页面标题，行里的图长成头图，上一页的标题缩成返回按钮。页面滚动时大标题收进顶栏、在控件行居中。返回时全部反向。
- **b. 卡片 → 全屏或对话框**：卡片本身（外框、圆角、图片）长成视图，标题还是那一行字、只缩放，其余内容在卡片基本展开后淡入。关闭或下拉时缩回原来那张卡片、原来那个位置。
- **c. 紧凑条 → 完整面板**（迷你播放器、聊天气泡、上传下载胶囊、带详情的 toast）：条就是面板，封面、标题、主按钮长到面板里各自的位置。面板全程不透明，背后的页面后退（缩到约 0.94、压暗约 30%）。
- **d. 搜索或筛选**：输入框上移到顶栏，页面标题离开，取消或关闭按钮滑入；输入时匹配项从原位滑到结果里的位置，其余淡出。桌面上命令面板从它的输入框打开也一样。
- **e. 摘要 → 详情**（指标卡 → 图表、进度环 → 报告、缩略图 → 图库）：小图形变成大图形（迷你折线就是图表那条线，小柱就是图表的柱），标签移成标题，数字放大而不是重画。
- **f. 控件 → 它控制的东西**（⋯ 或 + 按钮 → 菜单或表单、选择框 → 列表、日期字段 → 日期选择器）：面板从控件自己的那个角长出来，基本展开后各项依次淡入（间隔约 25ms），高亮随指针或手指在项之间滑动。操作新增、删除、移动了东西时，它在自己的位置出现，其余的挪开让位，什么都不跳。
- **g. 标签、分段控件、底栏、侧边导航**：一个指示器从旧标签移到新标签：前沿先走、后沿跟上，途中拉长、落位时收回（最长时压扁约 15% 的高度就够）；标签文字收起、展开时其余项让位。新内容从被选标签那一侧进来。
- **h. 布局变化**（网格 ↔ 列表、排序、重排、插入、删除、展开收起）：每一项从原位置移到新位置；换行的项从本行末尾离开、从下一行开头进来，不斜穿网格。

## 2. 怎么做成连续的

- **一个元素，不是两个**：移动的就是同一个元素（或框架按 id 匹配的共享元素），在起点和终点各量一次，用 transform 在两个盒子之间动画；会重排的元素绝不动画 width、height、top、margin。
- **只属于一个状态的东西才淡入淡出**：只在终态存在的内容在移动的 45–55% 之后淡入，只在起始存在的在前 25–35% 淡出。变大小的文字缩放，不和副本交叉淡化。
- **图层诚实**：长大的面板全程不透明，看不透；移动的元素在移动期间盖在邻居之上，落地后回到原来的层级。
- **形状保留圆角**：圆角在起止之间平滑变化，用产品自己的圆角曲线；嵌套形状保持等距内边距和同心圆角。
- **时长和曲线**：打开和关闭快起长收，`cubic-bezier(.32, .72, 0, 1)` 或产品自己的弹簧。手机：变成全屏 450–700ms，菜单和 sheet 350–500ms，指示器 400–450ms。桌面约为三分之二，键盘触发再短一些。同一屏内的移动用 ease-in-out。错开间隔 20–50ms。
- **手势**：拖动时 1:1 跟手（被拖的卡片一路缩到约 0.82）；松手时带着松手速度，去离得更近的那一端。
- **打断**：新的操作从动画当前位置接管；什么都不等动画结束，输入永远不被挡住。
- **减少动态效果**：保留状态变化和约 150ms 的交叉淡化，去掉移动和缩放。
- **无障碍**：焦点移到新状态的标题或第一个控件，关闭时回到打开它的元素；读屏器照旧播报新状态。

## 3. 手机和桌面

- 手机：上面全部；手势（侧滑返回、下拉关闭）和按钮驱动同一个动画；每一帧都遵守安全区。
- 桌面：同样的模式，更小更快。卡片或行通常打开成侧面板或对话框而不是整窗，从卡片长到那个面板。不要缩放整个窗口。悬停不触发布局动画。动画中指针目标保持在原位，第二次点击能点中。分栏里只在变化的那一栏里动画。
- 调整窗口大小和响应式断点不是转场，不做动画。

## 5. 只做用户选的

- 一条一条做。每做完一条，列出改过的文件，并检查：

  - 快速连点、动画中途返回、手势做到一半取消。

## 6. 按平台实现（按用户的版本核对）

- Web：View Transitions API，给共享元素设 `view-transition-name`（同文档；页面分开时用跨文档），不支持时直接更新。否则用 FLIP：先量起点 → 应用变化 → 量终点 → 用 transform 动画反向差值（Motion 的 `layout` / `layoutId`、Svelte 的 `flip` / `crossfade`、Vue 的 `TransitionGroup` 都是这么做的）。路由驱动的页面，从路由的导航钩子里启动过渡。
- iOS：同一视图内的共享元素用 SwiftUI `matchedGeometryEffect`；iOS 18+ 的 push 和 sheet 用 `navigationTransition(.zoom(sourceID:in:))` 配 `matchedTransitionSource`；UIKit 在 iOS 18 用 `preferredTransition = .zoom`，或自定义 `UIViewControllerAnimatedTransitioning` + `UIViewPropertyAnimator` 做可打断、手势驱动的转场。
- Android：Compose `SharedTransitionLayout` + `Modifier.sharedElement` / `sharedBounds`、`AnimatedContent`，列表用 `Modifier.animateItem`，手势返回用预测性返回；View 体系用 `MaterialContainerTransform` 和共享元素转场。
- Flutter：路由之间的共享元素用 `Hero`，卡片到页面用 animations 包的 `OpenContainer`，布局变化用 `AnimatedList` 和隐式动画。
- 桌面应用：Electron、Tauri 走 Web 路线（Tauri 用系统 WebView，要实测 View Transitions 并保留降级）；原生应用用各自的动画工具实现同样的思路。

## 7. 实现要点（demo 的做法）

- 一个通用的 `go(el, 目标, 时长, { from })`：先读出元素当前画面上的 transform / clip-path / opacity（可能正在半路），取消旧动画，去掉 transform 量出布局盒子，再用 WAAPI 动画到目标。打开时 `from` 由起点元素的矩形反算；正在动画时忽略 `from`、从当前画面接着走，所以关闭、打断、连点都不跳。
- 曲线：用从静止起步的弹簧（阻尼 0.9，按时长定刚度，时长内收到 0.2% 以内），采样成 CSS `linear()` 交给 WAAPI；不支持 `linear()` 时退回 `cubic-bezier(.32, .72, 0, 1)`。这条贝塞尔起步斜率是 2.25，全屏转场第一帧（16ms）就走掉约 6%，大约 30px，点下去像先跳了一下；弹簧第一帧只走几像素，之后同样快，尾巴同样长。
- 起点状态里的每一样东西都要有去处：要么飞到终态里对应的元素上，要么在原处淡出。把起点容器整个藏起来、只让几个元素飞走，没被照顾到的那几样（迷你播放条上的歌手名、「下一首」按钮）就会在第 0 帧凭空消失。
- 行 → 详情页：新页带左侧阴影从右边推入，旧页同时左移 28%；行标题、缩略图、上一页标题不随页面走，而是各自飞到大标题、头图、返回按钮的位置。不要让旧页淡出、新页背景淡入，那就是整屏交叉淡化。返回时，目标位置要减掉旧页此刻的位移（它可能还停在左边或在半路）。
- 控件 → 菜单：菜单从按钮那个角缩放长出，同时在前 25% 里淡入；否则第一帧会有一块按钮大小的白色直接盖住按钮。
- 文字和图片只做等比缩放（`transform-origin: 0 0`）：缩略图和头图、卡片图和详情头图用同一个 `aspect-ratio`，标题按字号比缩放，并补上两边行高不同造成的半行距差，否则交接时会错开约 1px。卡片展开时，详情文字块的字号和内边距按「卡片宽 / 面板宽」放大（CSS 变量 `--t015-s`），整块缩回卡片大小时和卡片里那几行字完全重合。
- 长大的外框用 `clip-path: inset(… round r)` 从卡片矩形展开到面板，内容按终态布局摆好，不会因为缩放把圆角和文字压扁；圆角跟着 clip-path 一起插值。
- 只属于终态的内容延迟到 50% 淡入，只属于起始的在前 30% 淡出；面板全程不透明。
- 拖动关闭：下拉时 1:1 跟手、按进度缩到 0.82；松手按「当前进度 + 速度 × 0.15s」判断去哪一端，用同一条曲线收尾。
- 布局变化（搜索过滤、新增项）：先记下每个元素当前画面上的矩形，改 DOM，再从旧位置滑到新位置；不再匹配的项改成绝对定位留在原处淡出，新出现的在后半段淡入。
- 标签栏指示器：胶囊是一个整宽元素，用 `clip-path: inset(上 calc(100% - 右沿) 下 左沿 round 999px)` 裁出来，左右沿和上下压扁是三个用 `@property` 注册的长度变量，各自用 WAAPI 动画：前沿先走、后沿晚 90ms，中途变长；上下各压 7.5%。
- 性能：正在动的内容上方不要压 `backdrop-filter`（顶栏、悬浮关闭按钮），它每帧都要重新模糊；用近乎不透明的底色代替。
- 淡出要停在 0：一段只占转场前 30% 的淡出播完后，如果直接取消动画、交还内联样式，元素会回到不透明，在转场后半段重新冒出来（返回箭头带着焦点框留在列表上、菜单项在收起途中闪回）。播完把终值写进内联样式，收尾时再统一清掉。
- 验收分两遍，都在控制台对 `document.getAnimations()` 做：
  - 几何：统一 `pause()`，按 16ms 一步设 `currentTime`，记录关键元素的可见矩形（带 clip-path 的要扣掉裁掉的部分）。三项都要过：第 0 帧移动元素和起点元素重合，最后一帧和终点元素重合（误差 ≤ 0.5px），第一帧位移只有几像素。
  - 时序：不暂停，每步把 `currentTime` 推到同一时刻，再等两个任务，让动画真的播完、结束回调和收尾照常执行。检查有没有元素淡出后又回升、出现后又消失，以及收尾后页面是否真的藏起来、焦点是否回到起点。只做第一遍发现不了上一条的问题，因为暂停的动画永远不会触发结束。
  - 预览窗口隐藏时 rAF 和文档时间线都不走，这两遍照样能做；靠 `setTimeout` 等待的实时检查在隐藏窗口里不可信。
- 演示里有「连续 / 硬切」对照和 ¼ 速慢放。参考实现见 `assets/015-continuity.html`。

## 常见错误

- 起点和终点是两个不同的元素交叉淡化，看起来是「消失再出现」。
- 页面切换做成旧页淡出、新页淡入的整屏交叉淡化，只让标题飞过去：整体看还是硬切。
- 起点容器一下子藏起来，里面有几样东西没安排去处，第 0 帧就凭空消失。
- 起步速度不为 0 的曲线配上大位移：第一帧就跳出去几十像素。
- 淡出比转场短，播完后元素又回到不透明，在转场后半段闪回。
- 动画 width / height / top 导致整页重排；或者非等比缩放图片和文字，把它们压扁。
- 面板展开过程中半透明，透出背后的列表。
- 内容一开始就全部出现，或者全部最后才出现；应该只有「只属于一个状态」的内容淡入淡出。
- 动画期间屏蔽点击、或者新操作要等上一个动画结束。
- 返回时不是原路收回：缩回的位置不是原来那张卡片、或者卡片已经滚出屏幕时飞向错误的位置。
- 悬停触发布局动画；窗口缩放、响应式断点也做了动画。
- 减少动态效果下还在移动和缩放。
